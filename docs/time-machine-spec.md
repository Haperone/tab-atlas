# ТЗ: Time machine — история состояния Tab Atlas

Дата: 5 октября 2026 года. Статус: продуктовая модель и конфликт папок согласованы
по ответам пользователя. История коллекций, отдельная база и долговечное
восстановление/Undo подключены к worker/UI. Прежний браузерный recorder отключён.
Реализация и browser fixtures проверены; приёмка установленного расширения ещё
не завершена. Актуальные границы: [progress](atlas-history-progress.md).

**Актуальная модель по последним уточнениям пользователя.**
Пользователь исключил архив из Time machine: отдельный архив в слепках не нужен,
как и затраты на хранение архивных записей. Пользователь также отверг текущую UX
модель просмотра: должно быть понятно, какие исторические папки/ссылки существуют
сейчас, какие отсутствуют и какие изменились. Старые отчёты с archive switch/grace
не подтверждают новую модель; проверять текущие требования и свежие артефакты.
Семантика восстановления уточнена пользователем: ссылка, восстановленная из
активного исторического состояния, появляется активной в своей прежней папке.
Если прежняя папка удалена, восстановление включает её возвращение, а не перенос
ссылки в Saved for later. Только исторические ссылки без папки остаются без папки.
Если сейчас тот же id находится в архиве, восстановление не должно
оставлять результат в архиве или создавать вторую запись с тем же id. Текущее
архивное состояние этой выбранной ссылки заменяется активным после подтверждения;
остальные архивные записи не затрагиваются. Архивные записи не включать в слепки.
Обычный архив dashboard пользователь не просил удалять.
Уточнение UX: если все исторические ссылки папки присутствуют в активном Atlas,
папка скрывается; если ни одной нет — вся папка красная. Строки внутри
полностью отсутствующей папки остаются без отдельной заливки. В смешанной папке фон нейтральный,
а присутствующие ссылки зелёные и отсутствующие красные. Пустые папки сравниваются
по наличию самой папки. Сравнение учитывает все ссылки, включая скрытые поиском
или пагинацией. Присутствие
не означает полное совпадение: перенос, переименование и другие отличия доступны
в пояснении при наведении/фокусе и в предварительном просмотре восстановления.
Постоянные короткие подписи статусов не добавлять. Сравнение по стабильным
id; совпадающий URL сам по себе не объединяет разные записи. Если ссылки сохранились
в другом месте, они считаются присутствующими; наличие самой папки и перемещения
доступны в пояснениях. Совпадающие ссылки видны только внутри смешанных групп.
Saved for later скрывается, если все его исторические ссылки присутствуют сейчас.
Существующие пустые папки скрываются, удалённые пустые папки доступны для восстановления.
Полное восстановление использует весь слепок, включая скрытые группы. Фон должен быть различимым и
согласованным с материалом каждой темы. Для доступности статус передавать также
в доступном имени элемента; пояснение показывать при наведении/фокусе, без
постоянных видимых подписей и дополнительных значков статуса.
Следующая согласованная корректировка: запись включена по умолчанию с первого
запуска, без opt-in/кнопки Enable local history. Пользователь сам ставит запись на
паузу или выключает через меню; явный off/pause сохраняется после перезапуска.
Старые отчёты про opt-in больше не являются требованиями.

Прежний прототип записывает браузерные вкладки и не соответствует этому ТЗ.
[Старое ТЗ](time-machine-browser-history-spec-superseded.md) и
[прежний отчёт](time-machine-review.md) сохранены как основания старой модели;
их тесты и измерения не доказывают готовность истории коллекций.

## 1. Согласованные решения

Ответы пользователя от 5 октября 2026:

1. Слепки содержат папки, активные сохранённые ссылки и их порядок, без архива.
2. Создание только автоматическое; ручной кнопки сохранения слепка нет.
3. Можно восстановить весь Atlas, выбранные элементы либо просто открыть любую
   ссылку из слепка в текущем обычном окне браузера.
4. После восстановления обязательно можно вернуть состояние до него через Undo.
   Случайный откат на месяцы назад не должен лишать возможности вернуться.
5. Если восстанавливаемая папка уже существует с таким названием, пользователь
   выбирает замену, добавление недостающих ссылок или отдельную копию с префиксом.

Сценарий: «Я удалил папку, потерял ссылки или перестроил коллекцию.
Хочу увидеть прежний Atlas и вернуть всё состояние либо нужные элементы».

## 2. Данные

Слепок — версия данных, а не изображение. Сохраняются:

- Папки: стабильные id, название, цвет, порядок, блокировка, свёрнутость.
- Ссылки: стабильные id, полный адрес, название, принадлежность папке/inbox,
  порядок, даты и существующие содержательные метаданные.
- Архив исключён из обычных слепков. Текущий dashboard архив продолжает работать.

Следовать реальным `folders`/`deferred`. Проверено в текущем коде: архив содержит
`completed` записи без `dismissed`; dismissed — legacy tombstones, удаляемые
при запуске. Они не являются архивом.
Одинаковый URL в разных записях не означает один элемент: идентичность — id.

Исключены браузерные вкладки и окна, pin/groups Chrome, история переходов,
настройки, тема, поиск/прокрутка, ручные workspace snapshots, содержимое сайтов.
Исторический Atlas отображается в текущей теме пользователя. Обычные workspace
остаются отдельной функцией; Time machine не запускает их восстановление.

## 3. Интерфейс

- Вход Customize → Time machine; отдельная поверхность внутри текущей вкладки.
  Не добавлять постоянную панель на dashboard и не создавать browser windows.
- На широком экране две равные части: Saved for later слева обычным списком без
  карточки/фоновой обёртки; папки справа в карточках. Прокрутка независима,
  timeline и поиск остаются над ними. Подсветка у Saved for later — на строках.
  Список не расходует лимит пагинации папок; выбор может включать обе части.
  Saved for later всегда раскрыт полностью, без кнопки «показать ещё». В каждой
  показанной папке сразу видны все отсутствующие (красные) ссылки; только
  оставшиеся присутствующие ссылки раскрываются дальше порциями по 25.
  Большие списки строятся постепенно с передачей управления браузеру.
  На широком экране позиции и ширины частей постоянны: при скрытии пустой части
  другая остаётся на своём месте и не расширяется. До 760 CSS px блоки идут друг под другом с общей прокруткой
  содержимого, чтобы не создавать две тесные вложенные области.
- Дата, timeline, Earlier/Later/Latest, поиск, исторические папки и inbox;
  без переключателя архива; настройки — в меню. Полностью совпадающие группы скрыты,
  полностью отсутствующие папки красные, смешанные — с подсветкой отдельных ссылок, без постоянных
  подписей статусов. Детали изменений — при наведении/фокусе и перед восстановлением.
- Timeline — календарная шкала с приближением: годы → месяцы → дни → часы и
  секунды и отдельные моменты. Минимальный видимый диапазон — одна секунда;
  делений меньше секунды нет. Если вся история короче секунды, показываем её
  реальный диапазон. Все слепки внутри секунды сохраняются; Earlier/Later и
  стрелки выбирают каждый из них отдельно. Колесо приближает вокруг курсора, −/+ вокруг выбранного
  момента (или центра видимой области); перетягивание двигает период. Годовые
  и календарные отметки позволяют приблизить соответствующий период. `All history`
  возвращает весь доступный диапазон, не меняя выбранный слепок.
  Одиночные слепки — маленькие точки, скопления — тонкие группы штрихов без
  постоянных цифр и фоновых плашек. Количество/дата доступны при наведении и фокусе.
  Нажатие на скопление приближает его до секундного предела; на пределе фокусирует
  ползунок и подсказывает точную навигацию стрелками/Earlier/Later.
  Нажатие на отдельную точку выбирает точный момент.
  Короткое нажатие по пустой шкале выбирает ближайший реальный слепок, а drag,
  включая drag по точке/скоплению, только перемещает период. Движение ползунка
  показывает дату, загрузка происходит при отпускании. Предыдущий/следующий слепок
  и клавиши-стрелки шагают ровно по одной записи; Home/End — крайние записи,
  Page Up/Down — перемещение периода, +/− — масштаб. Calendar ticks учитывают
  длину месяцев и местный часовой пояс; подробные даты включают offset и миллисекунды.
  Метаданные точек агрегируются в ограниченные buckets через IndexedDB key cursor,
  без чтения содержимого ссылок/patches; ближайший момент ищется по индексу.
- `Restore Atlas`, `Restore selected`, `Open link` — разные действия.
  В правом свободном поле широкого экрана — спокойная текстовая подсказка
  `How it works`: сравнение с текущим Atlas, скрытие групп без отсутствующих
  ссылок, красный/зелёный, точная навигация, выборочное/полное восстановление,
  Undo и открытие ссылки. Она не уменьшает рабочие столбцы. При недостатке места
  подсказка свёрнута рядом с датой; раскрытие сохраняет возможность прокрутки.
  В коротких окнах (высота до 640 px), а также при предупреждении о хранилище
  на высоте до 800 px, рабочие столбцы прокручиваются вместе с содержимым.
  В остальных широких окнах сохраняется независимая прокрутка двух столбцов.
  Закреплённые шапка и выбранное действие не могут сжимать списки до нулевой высоты.
  Если слепок совпадает с текущим активным Atlas (содержимое, свойства и порядок),
  панель восстановления скрыта. Сравниваем данные, а не дату: при выключенной записи
  даже последний слепок может отличаться и оставаться доступным для восстановления.
  Для отличающегося слепка `Restore entire Atlas` находится в закреплённой шапке
  как второстепенное действие без постоянной акцентной заливки. Нижняя панель
  появляется только после выбора элементов и предлагает `Restore selected`.
  Рядом дата слепка и объём действия; счётчик показывает папки
  и ссылки без двойного подсчёта содержимого выбранных папок. Сброс выбора
  скрывает нижнюю панель и возвращает фокус к выбранному элементу. Текст кнопок
  отображается полностью, без многоточий, с переносом. На узком экране выбранное действие занимает доступную
  ширину. Панель не перекрывает ссылки; подтверждение и Undo обязательны.
- Preview, поиск и выбор не меняют текущие данные и не открывают страницы.
- Details показываются при keyboard focus во всплывающей тематической подсказке,
  не меняя высоту строки/положение checkbox. Options закрывается кликом снаружи;
  Escape сначала закрывает открытое меню, сохраняя выбранный момент.
- Во время поиска соседнего момента сразу показывать loading и временно
  отключать действия старого содержимого. Поздние ответы закрытого Time machine
  не меняют новый вход. Совпадающий слепок предлагает выбрать более ранний;
  пустой поиск называет запрос и позволяет очистить его без потери фокуса.
- Подтверждение: дата, последствия, защита текущего Atlas для Undo, только
  ненулевые изменения; при выборе отдельных ссылок — их названия (первые пять
  и количество остальных). Галочки ссылок имеют область нажатия 24×24 px;
  выбранные строки получают тонкую акцентную рамку, сохраняя красный/зелёный статус.
  Одна прокручиваемая область; действия доступны на коротком
  экране. Restore a copy скрывает неиспользуемую существующую цель. Ошибка выбора
  указывает конкретное поле, возвращает к нему фокус и очищается после исправления.
- Новый слепок обновляет верхнюю границу, сохраняя просматриваемый момент.
- Закрытие возвращает прежние фокус, поиск и прокрутку dashboard.
- Настройки истории: включение, пауза/продолжение, размер, очистка с подтверждением.
  Запись включена с первого запуска автоматически. Явный off/pause сохраняется;
  экрана активации и ручного сохранения слепка нет.
- Тексты интерфейса — английские, в существующей терминологии продукта.

## 4. Автоматическая запись

Источники — подтверждённые изменения Atlas через dashboard/popup/ПКМ: сохранение,
папки, rename, reorder/drop, завершение активной ссылки, Undo, import, restore.
Изменения только архивных полей и очистка архива слепки не создают.
Открытие/закрытие браузерных вкладок само по себе слепки не создаёт.

- Первый запуск создаёт baseline активных коллекций. Идентичные состояния
  не записывать; темы, поиск, прокрутка не создают историю.
- Изменения одной операции объединять: rename после подтверждения, drag после
  drop, не каждый символ. Состояния до/после удаления, импорта и restore
  сохранять отдельно; batching не уничтожает нужное прошлое.
- Работать при закрытом dashboard. Пауза сохраняет прошлое; продолжение
  создаёт актуальную точку, неизвестные промежуточные данные не выдумываются.
- Один сериализованный владелец истории в worker. Учесть два dashboard,
  popup/ПКМ, пробуждение и остановку worker. Не полагаться на beforeunload.
- Проверить все существующие писатели `folders`/`deferred` и их группировку.
  Наивный debounce `chrome.storage.onChanged` может смешать массивы разных
  операций; контракт сохранения согласованного состояния обязателен.

## 5. Полное восстановление

1. `Restore Atlas` показывает дату, числа добавленных/удалённых/изменённых
   элементов и последствия замены активных папок, ссылок и порядка.
   Исторические активные id реактивируются из текущего архива без дубликата;
   невыбранные текущие архивные записи остаются неизменными.
2. Подтверждение `Restore Atlas` / `Cancel`, начальный фокус на безопасном действии.
3. До записи сохранить актуальные коллекции в долговечной защищённой точке
   `Before restore` и проверить возможность записать целевое состояние.
4. Восстановить `folders`/`deferred` согласованно. Workspace, настройки и
   браузерные окна/вкладки сохраняют своё состояние.
5. Добавить результат как новую точку настоящего времени; прошлое между
   выбранным слепком и восстановлением не удалять. Обновить dashboard и плашку.

Если места для возврата или целевых коллекций нет, остановить операцию до
изменений. Устаревший preview/диалог не должен перезаписывать более новые правки.

## 6. Выборочное восстановление и конфликт папок

Пользователь выбирает папки либо отдельные ссылки. Остальные коллекции сохраняются.
Если папки ещё нет, вернуть выбранную папку и её содержимое из слепка.
Если папка существует, не выбирать способ восстановления автоматически.

Обнаруживать совпадение имени по существующему правилу trim + lowercase.
Стабильный id также позволяет узнать ту же папку после переименования: такой
случай показать явно, а не перезаписывать её скрытно или создавать повтор id.
Если несколько текущих папок подходят по имени, пользователь выбирает конкретную
целевую папку; нельзя заменять первую случайную.

В компактном тематическом диалоге показать дату слепка, текущую целевую папку,
число текущих/исторических ссылок, последствия и три варианта:

| Вариант | Результат |
| --- | --- |
| `Replace folder` | Вернуть активное содержимое и поля выбранной папки к исторической версии. Новые активные ссылки этой папки, отсутствующие в слепке, убираются из текущего состояния, но остаются в Before restore. Остальные папки/inbox и невыбранные текущие архивные записи сохраняются. |
| `Add missing links` | Сохранить название, поля, порядок и текущие активные ссылки папки; добавить только отсутствующие исторические активные ссылки в их историческом относительном порядке. Если выбранный исторический id сейчас архивный, вернуть его активным без дубликата. |
| `Restore a copy` | Создать отдельную папку с префиксом, например `Restored · Работа`, и историческим содержимым. Исходная папка сохраняется. Для новой папки и её ссылок создать новые уникальные id. |

Для merge считать ссылку уже имеющейся в целевой папке при совпадении её
стабильного id либо полного адреса среди активных ссылок. Ссылка с таким
адресом в другой папке не мешает её добавлению в выбранную папку. Query/fragment
различаются. Это намеренное правило merge, а не глобальная дедупликация history.
Исторические повторы не удалять из полной замены или отдельной копии.

Если имя копии занято, использовать `Restored · Работа (2)`, `(3)` и т.д.;
проверить существующие ограничения длины имени и не разрезать Unicode-символ.
Показать конечное имя до подтверждения.

Целевая существующая папка сохраняет id и место в списке, чтобы не ломать
ссылки и не переставлять остальные папки. При конфликте id исторической ссылки
с активной записью вне выбранной папки создать новый id для восстановленной ссылки:
не переносить и не удалять активную запись вне выбора. Архивная запись с выбранным
историческим id реактивируется и возвращается в прежнюю папку без нового id.

Во всех трёх вариантах обязательны Before restore, долговечный Undo и проверка
актуальной ревизии после диалога. `Replace folder` требует явного подтверждения
последствий; Cancel ничего не меняет, начальный фокус не на замене.
Для нескольких выбранных папок решения задаются по каждой конфликтующей папке;
общий план применяется одной согласованной операцией с одним Before restore.

Locked правила остаются действующими: добавление разрешено, замена защищённой
папки недоступна с объяснением; можно восстановить копию. Не снимать lock скрытно.
Отдельная ссылка не возвращает все соседние ссылки папки. При отсутствии её папки
автоматически включить возвращение только прежней папки с выбранными ссылками
в подтверждение. Без конфликта не предлагать перенос в inbox. При совпадении имени
другой текущей папки разрешить конфликт явно. Восстановление ссылки с уже существующим id требует
явного выбора, если её поля или размещение изменились.

## 7. Открыть ссылку

Действие не восстанавливает коллекции. Создать активную вкладку в обычном окне,
содержащем Atlas, либо переключиться на уже открытый точный URL. Query/fragment
значимы. Не создавать новые окна. Если исходное окно недоступно — понятная ошибка.
Использовать существующий allowlist. HTTP/HTTPS поддерживаются; для сохранённых
file-ссылок учитывать действующий контракт и Chrome-доступ. Неподдерживаемый
адрес остаётся в слепке, даже если его нельзя открыть.

Поддерживаемые адреса представлены native ссылками: обычный click/Enter выполняет
указанный сервисный сценарий; Ctrl/Meta/Shift/middle click сохраняют стандартное
браузерное открытие. Disabled/loading блокирует и modifier-действия. Открытие
ссылки не восстанавливает коллекции. Полный URL доступен при hover/keyboard focus.

## 8. Долговечные Undo и возврат

- Перед каждым restore защитить актуальное состояние. `Before restore` и
  `Undo last restore` доступны после исчезновения плашки, закрытия dashboard,
  рестарта worker и браузера. Срок 5.5 секунды для этой гарантии неприемлем.
- Последняя гарантированная точка возврата защищена от обычной очистки бюджета.
- Undo возвращает состояние до restore и сам добавляет новую точку.
  Восстановленное старое состояние остаётся в timeline: можно снова выбрать его.
- Повтор Undo того же id не выполняет новые записи и не затрагивает чужие правки.
- Если после restore данные изменились, Undo не заменяет их молча: показать
  конфликт/последствия, сохранить новый актуальный Atlas перед подтверждённым возвратом.
- При следующем restore сначала защитить новую точку, затем переключить
  гарантию Undo. Другие моменты остаются в истории до обычной очистки бюджета.
- `Clear history` явно предупреждает об удалении точек возврата; текущие
  коллекции сохраняются. Не обещать защиту после удаления расширения/данных профиля.
- Общая зелёная нижняя плашка: таймер, hover/focus → Undo, стрелка назад,
  существующие звуки success/undo с учётом Sound off. Долгое действие — в меню.
- Старые краткие Undo dashboard/popup после замены коллекций не должны менять
  новую версию по совпавшим id. Проверить generation/revision или явно погасить
  устаревшие действия, сохранив долговечный Undo восстановления.
- Защищённая операция Undo отдельно хранит точное состояние до/после, включая
  архивное состояние реактивированной ссылки. Эти данные нужны для отмены, не
  показываются как архив в timeline и не копируются в обычные слепки. Undo может
  вернуть выбранную ссылку в прежний архив, отменяя её восстановление. Новую
  retention grace не создавать; существующий архив работает по обычным правилам.

## 9. Протокол и ошибки

IDB и chrome.storage.local не образуют общей транзакции. До изменений сохранять
id операции, исходную ревизию, Before restore, цель и дальнейший результат.
После обрыва worker определять исходное/целевое/конфликтное состояние по durable
данным. Не объявлять успех без подтверждения записи, не повторять операцию по id.

Все писатели коллекций должны участвовать в проверке ревизии: очередь только
в restorer не защищает от внешнего read-modify-write. Подтверждённые правки двух
dashboard, popup/ПКМ и restore не теряются. Ошибка истории не блокирует обычное
сохранение, но restore без подтверждённой защиты возврата запрещён.
Повреждение/blocked/newer schema: понятная ошибка, Retry/явная Clear;
никакого автоматического удаления всей базы.

## 10. Хранение

- Отдельная IndexedDB; текущие коллекции остаются в существующем хранилище.
- 200 МиБ учтённых UTF-8 записей; очистка к 160 МиБ. Словари, дельты, checkpoints,
  ключи, метаданные и защитный возврат входят в общий бюджет.
- В Time machine предупреждение с 80% бюджета; с 95% — `History almost full`.
  Красный semantic danger, процент и объём, пояснение автоматического удаления
  старых слепков и сохранения текущих коллекций/защищённого Undo. `History storage…`
  открывает существующий диалог; очистка требует подтверждения. Неизвестный объём
  не считается заполненным, предупреждение скрывается после уменьшения объёма.
  200 МиБ — бюджет приложения, а не максимальная квота IndexedDB в Chrome.
- Стабильные id и переиспользование неизменённых данных вместо полной копии
  Atlas на каждое мелкое изменение. Все оставшиеся точки реконструируются.
- Резерв возврата определяется размером реальных коллекций; прежние 256 КиБ
  browser ownership не являются достаточным резервом нового restore.
- Предлагается ограничение размером без обязательного удаления точек старше
  30 дней. Число доступных месяцев зависит от объёма и изменений и не гарантируется.
- GC удаляет недостижимые данные, сохраняя защищённый возврат. При квоте — одна
  ограниченная очистка и один повтор, затем понятная остановка.
- Схема IDB v2 добавляет индекс `records.bytes` для чтения размеров без payload.
  Обновление v1 создаёт индекс нативно, без переписывания слепков и операций.
  Граница автоочистки рассчитывается по счётчикам ссылок и точному ledger:
  metadata читаются один раз, старый префикс events/checkpoints удаляется
  диапазоном, недостижимые версии — за один проход. Операции и текущее состояние
  всегда участвуют в графе достижимости; удаление и ledger атомарны.
- Отличать payload, физический IDB overhead, origin estimate и local quota.
  Backup schema 1 содержит текущие коллекции, исключая history/операции.
- Локально, без новых зависимостей, permissions, аккаунтов, сети или аналитики.

## 11. better-review и измерения

Использовать `.agents/skills/better-*`, `apple-design`, AGENTS.md. Материалы

## 13. Переход с прежнего прототипа

Отключить browser tabs/windows/tabGroups recorder Time machine. Не конвертировать
его записи в вымышленные слепки папок и не удалять старые данные тихо.
Новая база/явная схема коллекций; UI timeline/themes/notification можно
переиспользовать после проверки. Browser ownership restorer не восстанавливает
коллекции. Пересмотреть старые tests/harness/docs; старый green verdict не переносить.
Ранее записанную историю коллекций с архивом перевести атомарно в активную
проекцию, сохранив даты/порядок моментов, настройки off/pause и защищённый Undo.
Недостижимые архивные версии освобождать GC. При повреждении миграция откатывается
без очистки; Retry и явная Clear остаются доступны.

Аудит источников записи и план интеграции: [implementation notes](time-machine-atlas-implementation-notes.md).

## 14. Будущая мобильная версия и синхронизация

Согласованное направление PWA, offline, opt-in sync, E2EE, hosting и платформенные
границы описаны в [ТЗ мобильного Tab Atlas и синхронизации](mobile-sync-spec.md).
Это отдельная будущая разработка, не текущая возможность расширения.
Time machine остаётся локальным на каждом устройстве; его 200 MiB не синхронизируются.
При включённом Sync восстановление/Undo меняет общую коллекцию, поэтому требует
явного описания межустройственных последствий и защиты от последующих правок.
Архив в обычные слепки не добавляется; синхронизация архива относится к актуальным
коллекциям, а не к истории. Новое ТЗ не меняет семантику прежних папок и protected Undo.
