# Устаревшее ТЗ: журнал браузерных вкладок

Отменено пользователем 5 октября 2026 года. Требуется история папок, сохранённых
ссылок, порядка и архива. Документ сохранён только как основание старого прототипа.
Новый проект: [time-machine-spec.md](time-machine-spec.md).

Дата: 3 октября 2026 года. Статус на 4 октября: реализовано в рабочем дереве, нативная приёмка Chrome ещё не завершена.

Этот документ определяет продукт, поведение, ограничения и критерии приёмки. Числа производительности ниже остаются требованиями. Фактические измерения, скриншоты и границы проверки находятся в [отчёте реализации](time-machine-review.md).

## 1. Задача и главный эффект

Пользователь открывает отдельный режим, перемещает ползунок времени и видит, какие вкладки были открыты в выбранный момент. Карточки появляются, исчезают и перемещаются вместе с перемоткой. Найденные страницы можно открыть снова.

Основной сценарий: «Вчера я исследовал тему, открыл много сайтов и всё закрыл. Хочу увидеть тот набор страниц и вернуть нужные».

Успех функции определяется тремя вещами:

- Прошлое узнаваемо по названиям, доменам, окнам и группам вкладок.
- Перемотка ощущается непосредственной: интерфейс отвечает на движение ползунка, а пользователь может прервать движение в любой момент.
- История имеет ограниченный объём, переживает перезапуски и не расходует квоту сохранённых ссылок в `chrome.storage.local`.

## 2. Зафиксированный объём первой версии

| Включить | Поведение |
| --- | --- |
| Открытые вкладки | История создания, закрытия, изменения адреса и названия |
| Окна | Принадлежность вкладки окну, создание и закрытие обычных окон |
| Порядок | Перемещение внутри окна и перенос между окнами |
| Закрепление | Историческое состояние pinned |
| Группы Chrome | Состав, название, цвет и свёрнутость группы |
| Активная вкладка | Запоминание выбранной вкладки окна без записи повторных одинаковых событий |
| Предпросмотр | Карточки по доменам; фильтр по историческому окну и поиск в выбранном состоянии |
| Восстановление | Одна вкладка, выбранные вкладки, карточка домена или весь выбранный момент |
| Управление историей | Включение, пауза, продолжение и очистка |

История сохранённых ссылок, папок Tab Atlas, архива и ручных workspace snapshots остаётся вне первой версии. При восстановлении они сохраняют своё текущее состояние. «Живой атлас» остаётся отдельной идеей для будущего.

Функция хранит метаданные вкладок. Содержимое сайтов, скриншоты, видео, история переходов внутри самой страницы, формы, пароли и положение прокрутки не входят в этот объём. Страница при восстановлении загружается в своём текущем виде.

История начинается после включения функции. Данные до установки или до включения записи недоступны. Доступность вчерашнего состояния зависит от того, велась ли запись и сохранился ли соответствующий отрезок.

## 3. Вход и настройки

1. Добавить пункт `Time machine` с контурной иконкой часов в существующий Customize. Постоянную панель на dashboard не добавлять.
2. Режим открывается как отдельная поверхность внутри dashboard с собственными заголовком, временной шкалой и историческими карточками. Существующие поисковые, архивные и диалоговые слои не должны оставаться интерактивными под ним.
3. При первом открытии показать краткое объяснение и кнопку `Enable history`. Запись по умолчанию выключена, в том числе после обновления у существующих пользователей.
4. Объяснить, что сохраняются названия и адреса обычных вкладок локально, с автоматическим удалением старой истории.
5. Настройки `Pause recording`, `Resume recording`, `Clear history` и сведения о размере разместить в меню самого режима. На обычный dashboard новые строки состояния не выводить.
6. Пауза сохраняет имеющуюся историю. Очистка удаляет историю, оставляет выбранное состояние записи и при включённой записи создаёт свежую начальную точку. Перед очисткой требуется тематический диалог с явным описанием удаления истории.
7. Закрытие режима возвращает прежнюю прокрутку, поисковый запрос и фокус dashboard. Запись после закрытия режима продолжается, если включена.

Тексты интерфейса использовать на английском, как в существующем продукте. Русский текст этого ТЗ предназначен для разработки.

## 4. Предпросмотр прошлого

### 4.1. Временная шкала

- При открытии выбрать последний доступный момент и сразу показать его дату, время и число вкладок.
- Шкала охватывает фактически доступную историю. Начало диапазона обновляется после очистки старых отрезков.
- Показывать небольшие отметки заметных изменений: массовое закрытие, восстановление, начало сеанса. Обычные изменения не должны создавать плотную стену маркеров.
- Внутри диапазона выбирать последнее зафиксированное состояние на выбранный момент. События с одинаковой временной отметкой упорядочиваются по последовательному номеру.
- Показать доступные переходы `Earlier`, `Later` и `Latest`. Шаги Earlier/Later переходят между изменениями, Latest — к последней записанной точке.
- Между сеансами и во время паузы показывать разрыв записи. Выбор внутри разрыва объясняет `History wasn't recorded during this period`; нельзя выдавать состояние до разрыва за достоверную картину внутри него.
- Исторические даты отображать в локальном часовом поясе пользователя; хранить время в UTC. Корректно обрабатывать смену часового пояса и перевод системных часов.

### 4.2. Карточки и действия

- Использовать узнаваемые карточки доменов и локальные иконки существующего dashboard. По умолчанию показывать все исторические окна; фильтр окна спрятать в компактном меню режима.
- Группировка по доменам — способ отображения. Исторические окна, порядок и группы Chrome сохраняются независимо от этой группировки.
- У ссылки есть историческое название, домен и действие открыть. Статус `Already open` обозначается текстом и иконкой, а не только цветом.
- Поиск фильтрует вкладки текущего исторического состояния. Поиск по всем событиям за всё время не входит в первую версию.
- Можно выбрать одну или несколько вкладок; кнопка `Restore N tabs` появляется только при наличии выбора. Действие `Restore this moment` находится в меню режима; действие карточки домена появляется при наведении или фокусе.
- Перемотка, поиск и выбор карточек сами по себе не изменяют реальные вкладки, окна, сохранённые ссылки и папки.
- Историческая дата остаётся явно видна при выборе и восстановлении. Пользователь должен понимать, что смотрит прошлое.
- Если во время просмотра появились новые события, сохранять выбранный момент. Обновлять доступную верхнюю границу, но не перемещать ползунок автоматически.
- Если выбранный момент удалён фоновым ограничением объёма, перейти к ближайшему доступному состоянию и сообщить `Older history was cleared to free space` один раз.

### 4.3. Пустые и ошибочные состояния

Различать: запись выключена, запись включена и ещё нет изменений, доступное состояние содержит ноль вкладок, запись на паузе, разрыв истории, загрузка, база недоступна, история повреждена и запись остановлена из-за нехватки места.

При ошибке показать понятную причину и Retry, если повтор может помочь. Очистка истории — отдельное явное действие пользователя. Автоматически удалять всю базу при ошибке чтения запрещено.

## 5. Анимация и консистентность тем

Главный эффект — управляемая перемотка карточек. Стабильные идентификаторы позволяют сохранять карточку визуально между соседними состояниями; изменения не должны каждый раз пересоздавать весь экран.

- Карточки сохранившихся вкладок плавно меняют положение; новые мягко появляются; закрытые исчезают. Никакого автоматического проигрывания шкалы.
- Продолжительность короткого перехода — до 150 мс; движение прерывается новым вводом. При быстром перетаскивании приоритет у последнего выбранного момента.
- При массовых изменениях использовать переход карточек доменов и обновление содержимого. Сотни индивидуальных анимаций одновременно не запускать.
- Не проигрывать звук на каждом движении ползунка. При успешном восстановлении использовать существующий сигнал подтверждения; Undo сопровождается существующим звуком отмены.
- При `prefers-reduced-motion` или настройке reduced motion проекта отключить перемещения и масштабирование. Дата, счётчики и карточки обновляются без ожидания анимации.
- Использовать семантические токены каждой темы: Glass сохраняет полупрозрачность, Soft — направленные мягкие тени и тактильные состояния, Apple — свои непрозрачные поверхности. Не вводить единую «космическую» оболочку.
- Поддержать клавиатуру, видимый focus, Escape, локальный порядок Tab и возврат фокуса. Шкала должна иметь доступное имя и озвучиваемые выбранные дату/время; не озвучивать каждую промежуточную точку при непрерывном перетаскивании.
- Проверить все 16 существующих тем, текстовый контраст, forced colors, reduced motion, ширину 320 px и масштаб 200%.

При реализации применять проектные `.agents/skills/better-*` и `apple-design` к соответствующим поверхностям и движению, соблюдая AGENTS.md.

## 6. Запись истории

### 6.1. Источники и границы

Запись работает в фоне, включая время, когда dashboard закрыт. Основной источник — события Chrome tabs/windows/tabGroups. Чтение существующей Chrome History не требуется; новые разрешения history, host permissions и unlimitedStorage не добавлять.

- Слушатели событий регистрируются синхронно на верхнем уровне service worker.
- После включения создать начальное состояние из актуальных обычных окон.
- При старте браузера начать новый сеанс с актуальным контрольным состоянием. Старые сеансы доступны для просмотра.
- После паузы или отключения расширения начать новый отрезок записи. Пропущенные изменения не реконструировать как наблюдавшиеся события.
- После обычного пробуждения service worker восстановить состояние из базы и сверить его с Chrome. Пробуждение worker само по себе не начинает новую историю и не очищает существующую.
- Если сверка обнаружила расхождение, сохранить явную точку сверки. Время неизвестных изменений не выдумывать; неоднозначный интервал отметить как разрыв.

### 6.2. Идентичность и события

У каждой исторической вкладки, окна и группы есть стабильный внутренний ключ. Chrome tabId/windowId/groupId используются для связи с текущим браузером, но не выступают единственными историческими идентификаторами: после закрытия и перезапуска они могут стать недействительными или повториться.

Минимальные типы событий: создание, закрытие, изменение метаданных вкладки, изменение порядка/окна, выбор активной вкладки, изменение группы, начало сеанса и сверка. При переносе вкладка сохраняет свой исторический ключ; при повторном создании получает новый, даже если Chrome повторил числовой id.

- Каждое событие содержит последовательный номер, время, сеанс, тип, идентификаторы и изменившиеся поля.
- Повторные одинаковые события не записывать. Loading, favicon, audible и другие технические обновления без изменений выбранных метаданных не создают историю.
- Сохранять подтверждённый адрес вкладки; предварительный pendingUrl не считать завершённым переходом.
- Смена названия обновляет исторические метаданные, но не создаёт новую вкладку.
- Поток title/loading и массовые операции допускают пакетную запись. Значимые подтверждённые изменения адреса и последовательность открытия/закрытия должны сохраняться.
- Перед закрытием уже должна существовать сохранённая запись метаданных: onRemoved не содержит достаточных данных для восстановления URL и названия.
- Отдельно проверить onReplaced, перенос между окнами, закрытие целого окна и удаление группы. Они не должны создавать фантомные дубликаты, потерянные вкладки или отрицательные счётчики.
- Метаданные закрывшегося окна сохраняются в истории. Зависимость от успешного tabs.get для уже удалённой вкладки недопустима.

## 7. Хранилище и бюджет

### 7.1. Разделение данных

Журнал, словари, контрольные состояния, текущая модель записи и операции восстановления находятся в отдельной IndexedDB базы origin расширения. Имя базы: `tab-atlas-time-machine`; первая версия схемы — 1.

Существующие ключи `deferred`, `folders`, `workspaceSnapshots` и формат backup schema 1 остаются совместимыми. В `chrome.storage.local` допустим только небольшой объект предпочтений функции; сам журнал туда не переносить.

IndexedDB не является безлимитной. Бюджет приложения и доступная квота браузера — разные величины. `navigator.storage.estimate()` даёт оценку общего origin, а не точный размер одной базы. Не подписывать этот результат как размер только истории.

### 7.2. Начальные параметры

| Параметр | Первая версия |
| --- | --- |
| Максимальный учтённый объём истории | 20 МиБ = 20 × 1024 × 1024 байт |
| Целевой объём после очистки по размеру | Не более 16 МиБ |
| Максимальный возраст | 30 дней; фактический доступный диапазон может быть короче |
| Контрольное состояние | После 200 значимых событий либо при следующем событии после 5 минут с предыдущей точки |
| Максимальный replay между контрольными точками | 200 значимых событий в исправном отрезке |

В первой версии пользователь видит бюджет и доступный диапазон. Настройка произвольного бюджета и обещание гарантированных «30 дней истории» не нужны. Параметры должны быть централизованы, чтобы скорректировать их по измерениям без изменения модели данных.

### 7.3. Подсчёт и очистка

- Учёт включает UTF-8 размер сериализованных записей и их ключей, словари, контрольные точки, служебную текущую модель и операции восстановления. Нельзя считать только события и забывать словари/снимки.
- Учтённый размер является бюджетом полезных записей. Физический размер IndexedDB дополнительно содержит индексы и служебные данные; это явно указать в документации и измерить на контрольных наборах.
- Повторяющиеся строки хранить в словаре. После удаления отрезков удалять недостижимые записи словаря. Словарь не может бесконечно расти после очистки журнала.
- При превышении возраста или перед записью, выходящей за бюджет, удалить самые старые отрезки. Новый край истории должен иметь собственное контрольное состояние; все оставшиеся моменты должны быть реконструируемы.
- Контрольную точку, зависимые события, словарь и счётчики менять согласованно транзакциями. Оборванная очистка не должна оставлять историю со ссылками на удалённые данные.
- Предусмотреть резерв для служебных данных и операций восстановления внутри общего бюджета.
- Если даже минимальное актуальное состояние не помещается, остановить запись с понятным сообщением. Ссылки и тексты не обрезать скрытно ради лимита.
- При QuotaExceededError попробовать ограниченную очистку старых отрезков и один повтор. Если места всё ещё нет, остановить запись; никаких циклов бесконечных повторов.
- Недоступность оценки квоты не означает безлимит. Собственный бюджет продолжает действовать, ошибки записи обрабатываются.
- Ошибка или заполнение базы истории не должны блокировать обычное сохранение ссылок, popup, ПКМ, архив и workspace snapshots.

В существующем Manage storage добавить отдельный раздел истории с собственным размером/бюджетом и переходом к её очистке. Его значения не складывать с показателем квоты `chrome.storage.local`.

## 8. Модель данных и устойчивость

Логические разделы базы: metadata/schema, sessions/segments, current state, string dictionary, events, checkpoints и restore operations. Конкретные object stores можно объединять, если сохраняются следующие требования.

- Записывает один владелец — service worker. Dashboard запрашивает состояния и действия через проверяемые сообщения; несколько открытых dashboard не становятся конкурирующими писателями.
- Последовательный номер, изменения текущего состояния и события сохраняются одной транзакцией. Кэш в памяти worker — ускорение, а сохранённая модель — источник восстановления.
- Незавершённая транзакция не считается записанным событием. При повторном пробуждении проверять актуальную картину Chrome, а не доверять прежнему кэшу.
- Принятые события сериализуются; гонка с первоначальным tabs.query не должна перезаписывать более новые события устаревшим снимком.
- Индексы должны позволять найти ближайшую предыдущую контрольную точку и прочитать только её отрезок событий. Для одного положения ползунка не загружать все 30 дней в память.
- Реконструкция состояния — отдельная проверяемая функция. Обратная перемотка использует контрольную точку и журнал, а не требует хранить полную копию экрана для каждого шага.
- Результат старого запроса после нового движения ползунка не может заменить более новый выбор. Нужны идентификатор запроса и отмена/игнорирование устаревшего результата.
- Учесть открытые соединения IndexedDB при изменении версии: versionchange закрывает соединение; blocked upgrade даёт понятное состояние и повтор. Нельзя бесконечно зависнуть на открытии базы.
- Обновление расширения сохраняет записанную историю. Неизвестная более новая схема блокирует запись с объяснением, сохраняя имеющиеся данные.
- Изменение системных часов не нарушает последовательность событий. Неоднозначную временную границу обработать явно; порядок определяет sequence.
- Service worker может быть остановлен в любой момент. Не держать его живым бесконечным таймером; не полагаться на выгрузку dashboard или финальный beforeunload для сохранения.

## 9. Восстановление и Undo

### 9.1. Поведение

- Открытие одной исторической ссылки: если точный URL уже открыт в обычном окне, перейти к нему; иначе создать активную вкладку в текущем обычном окне.
- Уточнение пользователя от 5 октября 2026: кнопка `Restore 1 tab` для одной выбранной страницы создаёт вкладку в окне, содержащем Tab Atlas, с обычной плашкой и Undo. Dashboard остаётся активным для отмены. Если это окно закрыто или недоступно, показать ошибку без создания нового окна. Для нескольких выбранных страниц сохраняется массовое восстановление в новых окнах, даже если после пропуска точных повторов осталась одна отсутствующая страница.
- Массовое восстановление создаёт новые обычные окна по исторической структуре выбранного набора. Сохранять относительный порядок, закрепление и группы доступных вкладок. Существующие окна и вкладки не закрывать и не перемещать.
- По умолчанию восстанавливать только отсутствующие точные URL. Query и fragment имеют значение. Исторические повторы одного URL объединять в одну страницу; число пропущенных страниц показывать в результате. Семантически «похожие» адреса не объединять.
- Если всё уже открыто, сообщить об этом без создания пустого окна.
- Если выбранная восстановимая страница больше не существует на сайте, Chrome показывает актуальную страницу/ошибку сайта; функция не обещает архивную копию сайта.
- Для набора более 50 создаваемых вкладок показать тематическое подтверждение с количеством вкладок и окон. Для меньших наборов отдельное подтверждение не требуется.
- Во время выполнения блокировать повторную отправку той же операции; показывать прогресс и Stop. Stop прекращает дальнейшее создание, уже созданные вкладки остаются доступными для Undo.
- Ограничить параллельное создание вкладок, начальное значение — до 4 операций одновременно. Предусмотреть частичный успех и ошибки отдельных вкладок/групп.

### 9.2. Безопасные адреса

Восстанавливать HTTP/HTTPS ссылки. Incognito, внутренние страницы Chrome, страницы расширений, javascript/data/blob/file и другие неподдерживаемые схемы исключать из записи восстановимых вкладок. Использовать существующую проверку адресов проекта либо общий валидатор с явным allowlist.

### 9.3. Результат и отмена

- Использовать существующую компактную зелёную плашку снизу по центру: количество открытых/пропущенных/неудачных вкладок, анимированная полоса времени, hover → Undo и иконка стрелки назад.
- Срок, hover-пауза и доступность действия соответствуют действующей системе уведомлений. Операция остаётся в меню режима как `Undo last restore`, если краткая плашка уже скрылась.
- Undo закрывает только вкладки, созданные этой операцией. Уже открытые страницы не принадлежат операции.
- Если созданная вкладка после восстановления была перенесена пользователем, изменила адрес или закрепление, Undo оставляет её и сообщает число оставленных вкладок. Изменение title/favicon/loading само по себе не лишает права Undo; обычные редиректы при открытии должны быть учтены в модели владения.
- Undo пустых созданных окон происходит естественным закрытием принадлежавших операции вкладок. Чужие вкладки внутри такого окна сохраняются.
- На Undo проигрывается существующий звуковой сигнал отмены. После отмены повторный Undo той же операции не должен закрывать другие вкладки.
- Записывать известные созданные tab/window id и итог операции в IndexedDB. При остановке worker массовое восстановление не продолжается автоматически после пробуждения; показать прерванный результат и доступный безопасный Undo.
- Chrome APIs и IndexedDB не образуют общую транзакцию. Если создание прошло, а запись результата оборвалась, нельзя угадывать принадлежность по одному URL и закрывать чужую вкладку. Неопределённые вкладки остаются открытыми; результат обозначает неполноту отмены.
- Повтор сообщения с тем же request id не запускает второе восстановление. Частично выполненная операция повторяется только явным новым действием пользователя с повторной проверкой уже открытых адресов.
- Открытие и отмена восстановления записываются как реальные события новой истории, с идентификатором операции. Не стирать прошлое после Undo.

## 10. Приватность и совместимость

- Запись включается пользователем. Incognito исключается и на уровне приёма событий, и на уровне восстановления/запроса состояния.
- Вся история локальна. Не добавлять сеть, аналитику, удалённые favicon, шрифты или облачные зависимости.
- URL, query и названия вкладок могут содержать личные данные. Не выводить их в обычные логи и отчёты измерений; тестовые наборы содержат вымышленные страницы.
- После сброса/удаления IndexedDB показать отсутствие истории и создать новую начальную точку при включённой записи. Точное сохранение истории после eviction не гарантируется; обычные сохранённые коллекции должны оставаться рабочими.
- При включении можно запросить navigator.storage.persist(), обрабатывать отказ без поломки функции. Это защита от вытеснения, а не увеличение бюджета приложения.
- Обычный экспорт/импорт backup schema 1 сохраняет существующий контракт и не переносит историю. Это явно указать рядом с информацией об истории. Отдельный экспорт истории отложить.
- При реализации обновить privacy policy, README и существующие документы публикации: что именно записывается, как включается, где хранится и как удаляется. Не утверждать, что функция использует дополнительное разрешение history.
- Сохранить текущую минимальную версию Chrome, если доступные API её позволяют. Не менять manifest permissions или минимальную версию без обоснованной необходимости.
- Не добавлять зависимости, аккаунты, сервер, автоматически обновлять версию, формировать релиз, коммитить или пушить в рамках реализации этого ТЗ без отдельного запроса.

## 11. Производительность и измерения

Контрольные наборы: 100, 1 000 и 10 000 исторических вкладок; короткая и заполненная до бюджета история; массовое закрытие; длинные UTF-8 названия и адреса; большое число уникальных URL. 10 000 вкладок — синтетический набор для обработки данных, а не требование открыть их одновременно в Chrome.

Цели на задокументированной машине при прогретой базе:

- Для 1 000 вкладок и ограниченного 200 событиями replay результат seek доступен за ≤250 мс по p95.
- Первый полезный результат режима при истории около бюджета — ≤1 секунды по p95.
- При непрерывном движении ползунка не отображать результаты устаревших запросов; финальный выбор должен соответствовать последнему вводу.
- Не создавать DOM на десятки тысяч вкладок сразу. Для больших состояний использовать ленивый вывод/виртуализацию, сохраняя доступность выбора и поиска.
- В фоне нет периодического полного чтения всех вкладок без события или причины для сверки. Контрольные точки создаются при обработке событий, а не ради постоянного пробуждения worker.
- Ни одно большое действие не должно блокировать основной поток UI задачами более 50 мс на контрольном наборе; разбиение работы и измерения обязательны.

Зафиксировать CPU/окружение, число событий, размер полезных записей, доступную оценку origin, время записи/очистки/seek и память. Если цель не достигнута, сначала ограничить объём работы и оптимизировать; не скрывать результат повышением заявленного времени без объяснения.

| TM-18 | Исключения | Incognito и неподдерживаемые схемы не попадают в историю восстановимых вкладок |

| TM-22 | Обновление/база | Миграция, blocked connection, более новая схема и потеря базы дают предсказуемое поведение без тихого удаления данных |
| TM-23 | Документы/приватность | Локальная запись, ограничения, очистка и исключение истории из backup описаны; разрешения соответствуют реальному коду |

Автоматические тесты нужны для reducer/replay, словаря и очистки, идемпотентности, очереди событий, восстановлений и Undo. IndexedDB транзакции, прерывание worker и межконтекстные запросы обязательно проверяются в браузере: одних моков недостаточно.

Использовать существующий Node test runner и harness проекта. Визуальные проверки проводить на вымышленных данных. После модульных проверок выполнить `npm run verify`, необходимые браузерные сценарии и проверку отсутствия внешних автоматических запросов. Для reduced motion, ошибок хранения и частичного восстановления нужны отдельные сценарии.

Готовый результат включает код, тесты, обновлённые документы, измерения и скриншоты ключевых поверхностей в Glass, Soft и Apple. В итоговом отчёте перечислить непроверенное и оставшиеся ограничения; не выдавать моковые проверки за поведение установленного расширения.

## 13. Источники и основания

Текущий проект: `extension/manifest.json`, `extension/background.js`, `extension/app.js`, `extension/lib/storage-repository.js`, `extension/lib/storage-usage.js`, AGENTS.md и проектные интерфейсные скиллы.

Технические основания проверены 3 октября 2026 года:

- [Chrome Storage API](https://developer.chrome.com/docs/extensions/reference/api/storage): квота `chrome.storage.local` в современных версиях Chrome — 10 МиБ; текущий проект не использует unlimitedStorage.
- [Storage and cookies](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies): IndexedDB доступна service worker, имеет собственные ограничения; estimate относится к origin; persist защищает от вытеснения при предоставлении.
- [Service worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle): worker может завершаться, данные в глобальных переменных не являются устойчивым хранилищем.
- [Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs) и [TabGroups API](https://developer.chrome.com/docs/extensions/reference/api/tabGroups): события и операции вкладок/групп для записи и восстановления.
